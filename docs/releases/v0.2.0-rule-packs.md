## Published asset boundary

Each release contains exactly five assets:

```text
<SOURCE>.blp
<SOURCE>.coverage.json
<SOURCE>.provenance.json
<SOURCE>.SHA256SUMS
verifying-key.hex
```

No Broad report is a release asset or appears in `SHA256SUMS`. Broad reports remain untrusted validation-job output and do not cross the signing boundary.

## Independent verification performed

Fresh downloads were checked as follows for every source:

1. `sha256sum -c <SOURCE>.SHA256SUMS` passed for the pack, coverage, provenance, and verifying key.
2. `verifying-key.hex` was byte-identical to `rules/trusted-keys/<SOURCE>-rules.pub`.
3. `bashlume-pack verify` accepted the official signature and verified every command block.
4. The pack ID, embedded `v0.2.0` version, source commit, command count, and zero-stale state matched the release manifest.
5. Canonical provenance matched the pack byte length and SHA-256, rule commit, upstream commit, compiler commit, coverage digest, and official key identity.
6. Coverage schema 3 reported zero unsupported files and zero stale registrations.
7. GitHub's API asset size and `sha256:` digest matched each independently downloaded byte stream.
8. Each signed tag resolved to the exact rule commit recorded in provenance.

`rules/packs.lock` records the audited immutable release URLs and pack digests. The Stable Nix derivations consume that lock, verify each signature with the corresponding checked-in public key, and assert the expected pack ID, embedded release version, and zero-stale status before installation. The combined Nix output passed a real Bash PTY merge test for all three sources and an independent remove/reload/restore rollback test.
